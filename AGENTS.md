UI SDK on Compose Multiplatform: unstyled components from compose-unstyled + shadcn/ui styles.
The foundation is the unstyled compose kit without styles; the styles come from the figma shadcn export.
Styles are imported via a plugin and converter.
Main target is jvm — testing is done only on it. The ios target is not tested, but must stay supported.
If there are several implementation options or the goal is imprecise, always ask questions.
DI — Koin, networking — Ktor, JSON — kotlinx.serialization, navigation — androidx.navigation3 (nav3).
Versions are managed only through gradle/libs.versions.toml. Versions: Kotlin 2.4, AGP 9, CMP 1.11, JVM target 17.

## Modules
- `:uikit` — the library (targets: android, jvm, wasmJs, iosArm64/iosSimulatorArm64; NO js target — lazytable does not support it)
- `:demoApp:commonApp` — shared demo code (+ platform sources androidMain/iosMain/jvmMain/webMain with expect/actual)
- `:demoApp:androidApp|desktopApp|webApp` — entry points; iOS — `demoApp/iosApp` (Xcode)

## Commands
- Build uikit: `./gradlew :uikit:build`
- Desktop demo: `./gradlew :demoApp:desktopApp:run`
- Android demo: `./gradlew :demoApp:androidApp:assembleDebug`
- Wasm demo: `./gradlew :demoApp:webApp:wasmJsBrowserDevelopmentRun`
- Regenerate theme: `./gradlew importThemeFromFigmaTokens`
- shadcn reference snapshot: `./gradlew syncShadcnReference` (version pinned by the REF constant in SyncShadcnReference.kt; on update — new SHA → task → git diff shows reference changes)
- Icon catalog: `python3 scripts/generate_icon_catalog.py`
- Quick common compilation check: `./gradlew :uikit:compileKotlinJvm` (or compileKotlinWasmJs)
- Component plan and status — in `COMPONENTS.md` (source of truth; update on changes)

## Code conventions
- Source-of-truth hierarchy:
  1) `imports/design-tokens.json` (Figma) — token values;
  2) `imports/shadcn-reference/` — component classes/states/sizes (snapshot of shadcn-ui/ui);
  3) on conflict → fix the Figma export, not the uikit code
- A component is a folder `uikit/.../components/<name>/`: `<Name>.kt` (public API) +
  `<Name>Colors.kt` (internal data class + `resolve<N>Colors(variant, isHovered, isPressed)`)
- Colors only from tokens: `Theme[ColorProps][ColorTokens.xxx]`; dark/light — via `LocalThemeIsDark`.
  No hardcoded colors/sizes — everything from Figma tokens
- The base is compose-unstyled primitives (com.composables:*); do not use Material components directly
- Popups/toasts — via the existing DialogHost/ToastHost (wrapped in `ShadcnUI`)
- expect/actual for platform-specific code (example: DI.kt / DI.android.kt ...)

## Key paths
 - components `uikit/src/commonMain/kotlin/com/github/jershell/shadcn/components`
 - styles `uikit/src/commonMain/kotlin/com/github/jershell/shadcn/theme`
 - demoApp `demoApp/commonApp/src/commonMain/kotlin/com/github/jershell/shadcn/App.kt`
 - demoApp screens `demoApp/commonApp/src/commonMain/kotlin/com/github/jershell/shadcn/ui`
 - demoApp ComponentsRegistry `demoApp/commonApp/src/commonMain/kotlin/com/github/jershell/shadcn/ui`

## How to add a component (full cycle)
1. Component in `uikit/.../components/<name>/` (styles from the shadcn layout in Figma)
2. Demo `demoApp/.../ui/components/demo/Demo<Name>.kt` (following the pattern of neighboring demos)
3. Register in `ui/navigation/ComponentsRegistry.kt` (ComponentId/ComponentEntry)
4. Build the desktop demo for verification
5. Update the status in `COMPONENTS.md`

## Agent workflow
- Do NOT run a smoke test (launching the desktop app) — the master does manual checks.
- Do NOT commit: the master performs commits. Limit yourself to building
  (`:uikit:compileKotlinJvm`, `:demoApp:commonApp:compileKotlinJvm`).

## Generated code (do NOT edit by hand!)
- `uikit/.../shadcn/theme/Generated*.kt`, `Theme.kt`, `TokenShadow.kt` are generated by the
  `importThemeFromFigmaTokens` task (code in `build-plugin/`, input: `imports/design-tokens.json`).
